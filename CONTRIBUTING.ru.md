# Участие в разработке

[English](CONTRIBUTING.md) · **Русский**

Эти правила применяются ко всем репозиториям организации Pteris Health, если
репозиторий не определяет собственную версию.

## Процесс

1. Создайте ветку от `main` с префиксом: `feat/`, `fix/`, `chore/`, `docs/`,
   `refactor/`, `test/`, `perf/`, `ci/`.
2. Один пул-реквест — одно логическое изменение.
3. Добавляйте или обновляйте тесты при изменении поведения.
4. Убедитесь, что проверки проходят локально перед отправкой.
5. Откройте пул-реквест в `main` и заполните шаблон.

## Сообщения коммитов

Используйте [Conventional Commits](https://www.conventionalcommits.org/):

```text
<тип>(<необязательная область>): <краткое описание>
```

## Пул-реквесты

- Ссылайтесь на задачу, которую закрывает пул-реквест (`Closes #123`).
- Все проверки должны пройти, а обсуждения — быть разрешены.
- Только squash-merge. Заголовок пул-реквеста становится темой коммита.
- Коммиты должны быть подписаны (`git config --global commit.gpgsign true`).
- Требуется как минимум одно одобряющее ревью.

## Безопасность

Не создавайте публичные задачи по проблемам безопасности. См. [SECURITY.md](SECURITY.md).
